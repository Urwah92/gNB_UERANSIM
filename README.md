# UERANSIM: build and run UE, gNB and simulated Wi-Fi AP

This is **one source repository**. Run `make` in a container to build both `nr-ue` and `nr-gnb`. The YAML file selects the role:

| Node | Program | YAML choice | What starts |
| --- | --- | --- | --- |
| Cellular gNB | `nr-gnb` | `wifi: false` | Simulated radio, RRC, NGAP/SCTP and GTP-U |
| Cellular UE | `nr-ue` | `wifi: false` | Simulated radio, RRC, NAS and cellular PDU/TUN |
| Simulated Wi-Fi AP/router | `nr-gnb` | `wifi: true` | Simulated radio discovery and AP forwarding |
| Simulated Wi-Fi station | `nr-ue` | `wifi: true` | AP discovery and source-specific Linux routing |

Wi-Fi mode uses Linux interfaces and simulated AP selection. It does not create an 802.11 radio or register the UE with a 5G core. Cellular handover is the project's **UE-relayed inter-gNB simulation with NGAP Path Switch Request**; it does not exchange XnAP messages between the gNBs. See [integration details](docs/INTEGRATION.md) for how this works.

## 1. Prepare the source and a YAML file for each node

Keep only source files when sharing this repository. **`build/` is generated by `make` and should not be copied into another container or committed.** Also omit `.deps/` and `build.stale*/` if present. The project `.gitignore` excludes generated build files from Git, but `docker cp` copies them if they still exist in the folder.

Place the source directory and that node's configuration in the container. For example:

```text
UE container                 gNB or AP container
/                            /
├── UERANSIM/                ├── UERANSIM/
└── ue.yaml                  └── gnb.yml
```

The `.yaml` and `.yml` extensions both work; the `-c` option gives the actual path. A target gNB gets its **own** source copy and its own `/gnb.yml` inside its container. A Wi-Fi AP also uses the `nr-gnb` binary and a `/gnb.yml` with `wifi: true`.

If you use Docker, run the following **on the Docker host**, from the parent directory containing the source folder and your edited YAML files. Replace `ue1` and `gnb1` with your container names. Do this after removing the generated directories listed above:

```sh
docker cp UERANSIM ue1:/
docker cp ue.yaml ue1:/ue.yaml
docker cp UERANSIM gnb1:/
docker cp gnb.yml gnb1:/gnb.yml
```

Repeat the same copy steps for a target gNB or AP container, supplying that node's own `gnb.yml`. In GNS3 or another container manager, transferring the same files by its file-copy feature is equivalent. From a Git checkout, `git archive` is another way to export only tracked source files; it leaves `build/` out automatically.

If you do not already have edited YAML files, copy a [container example](config/container/) **inside the appropriate container** and edit it before starting:

```sh
# Cellular UE container:
cp /UERANSIM/config/container/ue-cellular.yaml /ue.yaml

# Source gNB container:
cp /UERANSIM/config/container/source-gnb.yml /gnb.yml

# Or, in a different gNB container:
cp /UERANSIM/config/container/target-gnb.yml /gnb.yml

# Or, in a separate Wi-Fi AP container:
cp /UERANSIM/config/container/wifi-ap.yml /gnb.yml

# Wi-Fi UE container uses this instead of ue-cellular.yaml:
cp /UERANSIM/config/container/ue-wifi.yaml /ue.yaml
```

Use one `ue.yaml` per UE container and one `gnb.yml` per gNB/AP container. Run the source and target gNB examples **together** for cellular handover; use the AP example with the Wi-Fi UE in a separate lab. Edit the example addresses, interfaces, PLMN and cellular subscriber values to match your lab. Sample subscriber keys are for a test lab only.

## 2. Install build tools and run `make` in each container

These commands assume a Debian/Ubuntu container with a root shell, like `root@ue1:/#`. Run them in **each** node container where you need the binaries:

```sh
apt-get update
apt-get install -y build-essential cmake libsctp-dev lksctp-tools iproute2 iptables procps python3 iputils-ping
cd /UERANSIM
make
```

You need CMake **3.17 or newer**, a C++17 compiler, and SCTP development headers (`libsctp-dev`). Bundled libraries under `src/ext/` are built from this source; no separate YAML development package or network download by CMake is needed. The first `make` creates `build/` in that container and places `nr-ue`, `nr-gnb`, `nr-cli`, `nr-binder` and `libdevbnd.so` there. **Do not copy that `build/` to another node.**

If the container has little memory, use `make JOBS=1` instead. To run the default tests after building, use `make test`. The default tests do not need a running 5G core or changes to your host networking. If you accidentally copied an older `build/`, the repository's `make` script preserves the stale cache as `build.stale*` and configures a fresh build; a source-only copy avoids this extra work. Direct `cmake` commands should also use a fresh build directory.

The container runtime must expose the networking features needed by the role:

| Role | Runtime requirement |
| --- | --- |
| Cellular gNB | Reachable AMF/UPF and host kernel SCTP support |
| Cellular UE | `/dev/net/tun` and network administration capability for the PDU TUN/routes |
| Wi-Fi AP | Network administration capability for `iptables` forwarding rules |
| Wi-Fi UE | Network administration capability for `ip route` and `ip rule` |

Being `root` **inside** a container does not itself grant `CAP_NET_ADMIN`. Provide the capability when creating the container. For example, a Docker-based cellular UE needs `--cap-add=NET_ADMIN --device=/dev/net/tun`, while an AP or Wi-Fi UE needs `--cap-add=NET_ADMIN`. Configure the equivalent permissions in your GNS3/container template. The host kernel, which containers share, must support SCTP for cellular gNB mode.

## 3. Check the example addresses and YAML

The examples use these two **separate** lab layouts:

| Cellular handover node | Local radio `linkIp` | Local N2 `ngapIp` and N3 `gtpIp` |
| --- | --- | --- |
| Source gNB | `10.1.1.10` | `10.100.1.4` |
| Target gNB | `10.1.1.14` | `10.100.1.5` |
| AMF | — | Remote AMF at `10.100.1.1:38412` |

The cellular UE must have IP connectivity to both `linkIp` addresses on UDP port `4997`. Both gNBs need their shown local addresses assigned and must reach the AMF. The core needs the UE's IMSI, key, OP/OPc, PLMN, DNN and slice provisioned consistently. The sample UE requests DNN `internet` and SST `1` without an SD. The core's UPF must also be reachable from each gNB for GTP-U.

| Separate Wi-Fi lab node | Local interface and address |
| --- | --- |
| AP facing UEs | `eth1 = 10.1.1.10/24` (`UeInterface`) |
| AP facing uplink | `eth2 = 10.100.1.4/24` (`nextHopInterface`) |
| Wi-Fi UE | `eth1 = 10.1.1.2/24` (`Interface` and `staticIP`) |

Use **your actual interface names**; `eth1` and `eth2` are examples. Configure and inspect addresses inside each container:

```sh
ip -br -4 addr
ip route
```

`staticIP: 10.1.1.2` in Wi-Fi UE YAML requires `10.1.1.2` to **already be assigned** to its `eth1` and the interface to be up. `staticIP` has no `/24` suffix in YAML. If your UE's address is not assigned, configure the interface through your lab/container networking before launching `nr-ue`; the program does not assign it.

For example, if these interfaces are currently unconfigured and the example addresses really belong to them, run these commands in the **indicated** containers:

```sh
# Wi-Fi UE container only:
ip link set eth1 up
ip addr add 10.1.1.2/24 dev eth1

# AP container only:
ip link set eth1 up
ip link set eth2 up
ip addr add 10.1.1.10/24 dev eth1
ip addr add 10.100.1.4/24 dev eth2
```

Skip an `ip addr add` command when that address is already assigned. Use your real addresses if they differ from the example.

In the AP container, enable IPv4 forwarding and provide an uplink route using your real upstream gateway. Your upstream router needs a return route for `10.1.1.0/24` via the AP, or NAT must be configured outside this program:

```sh
sysctl -w net.ipv4.ip_forward=1
ip route
```

For example, if `10.100.1.2` really is the AP's upstream router on `eth2`, you can set `ip route replace default via 10.100.1.2 dev eth2` **in the AP container**. The legacy AP keys `sessionIP` and `nextHop` are **not read** by this code. Put the UE address in its own `staticIP`; configure an AP next hop as a Linux route on `nextHopInterface` if your network requires it.

Validate each YAML after building. This checks the file and then exits without starting network tasks:

```sh
# In a UE container:
cd /UERANSIM
./build/nr-ue -c /ue.yaml --check-config

# In a gNB or AP container:
cd /UERANSIM
./build/nr-gnb -c /gnb.yml --check-config
```

`Configuration valid` means the YAML parses; it does **not** check the live interface IPs, route, AMF connection or subscriber record. For field-by-field explanations, limits and further examples, see [UE YAML parameters](docs/UE_CONFIGURATION.md) and [gNB/AP YAML parameters](docs/GNB_CONFIGURATION.md).

## 4A. Run the cellular gNBs and UE

Use `wifi: false` in all three cellular YAML files. In separate containers, after building and validating:

```sh
# Source gNB container, with source-gnb.yml copied to /gnb.yml:
cd /UERANSIM
./build/nr-gnb -c /gnb.yml

# Target gNB container, with target-gnb.yml copied to /gnb.yml:
cd /UERANSIM
./build/nr-gnb -c /gnb.yml

# Cellular UE container, with ue-cellular.yaml copied to /ue.yaml:
cd /UERANSIM
./build/nr-ue -c /ue.yaml
```

The UE example moves from position `(10, 2, 0)` toward `(180, 2, 0)` at `10` simulated metres/second. `gnbSearchList` names the source and target gNB `linkIp` addresses, **not** their N2/NGAP IPs. After registration and a PDU session, look for `Path Switch Request sent` and `Path switch complete` in logs. Check UE traffic before and after the switch; signaling messages alone do not prove the data path works. Your AMF/SMF/UPF must support path switching and update the UPF tunnel for live continuity.

## 4B. Run the simulated Wi-Fi AP and station

Use `wifi: true` in **both** the AP's `/gnb.yml` and the Wi-Fi UE's `/ue.yaml`, in a separate Wi-Fi lab. Start the AP first:

```sh
# AP container, with wifi-ap.yml copied to /gnb.yml:
cd /UERANSIM
./build/nr-gnb -c /gnb.yml

# Wi-Fi UE container, with ue-wifi.yaml copied to /ue.yaml:
cd /UERANSIM
./build/nr-ue -c /ue.yaml
```

When the station discovers the AP, it installs a source-specific rule and a default route in `wifiRoutingTable` (example `10001`). In another shell in the **Wi-Fi UE container**, inspect the selection and send traffic from `staticIP`:

```sh
ip rule show
ip route show table 10001
ping -I 10.1.1.2 10.100.1.2
```

The last address is an **example upstream host**; replace it with one that is reachable and answers ping in your lab. An upstream test requires forwarding plus a return route or NAT. A Wi-Fi station is one UE per `nr-ue` process (`-n` greater than `1` is rejected in Wi-Fi mode).

## YAML field guide at a glance

| Field | Where it belongs | What to put there |
| --- | --- | --- |
| `wifi` | Both YAML files | `false` for cellular, `true` for the simulated AP/station pair. |
| `mcc`, `mnc` | Both | Quoted PLMN strings such as `'001'` and `'01'`. |
| `nci`, `idLength`, `tac` | gNB/AP | Cell/gNB identity and tracking area. With `idLength: 32`, `nci: '0x000000030'` gives AP ID `3` and firewall chain `UERANSIM_3`. |
| `linkIp` | gNB/AP | **Local** radio IP bound by `nr-gnb`, e.g. `10.1.1.10`. |
| `ngapIp`, `gtpIp` | gNB/AP | **Local** N2/N3 IPs, e.g. `10.100.1.4`; required even when AP mode does not use those tasks. |
| `amfConfigs` | gNB/AP | **Remote** AMF address/port in cellular mode, or `[]` in AP mode. |
| `slices` | gNB/AP | Cellular SST/optional SD, or `[]` in AP mode. |
| `UeInterface`, `nextHopInterface` | AP | Two distinct AP Linux interfaces, e.g. `eth1` and `eth2`. |
| `gnbSearchList` | UE | Reachable gNB/AP `linkIp` addresses, e.g. `[10.1.1.10, 10.1.1.14]`. |
| `supi`, `key`, `op`, `opType`, `amf` | UE | Subscriber credentials; `amf` here is a **hex authentication field**, not an AMF IP. |
| `sessions` | Cellular UE | PDU type, DNN (`apn`) and slice, e.g. IPv4/internet/SST 1. |
| `phyLocation`, `velocity`, `pattern` | Both | Simulated position and UE movement. gNB coordinates are single numbers; UE coordinates are waypoint arrays. |
| `staticIP`, `Interface`, `wifiRoutingTable` | Wi-Fi UE | Existing source IP, interface carrying it and policy routing table. |

The [UE field reference](docs/UE_CONFIGURATION.md) explains **every UE YAML field**, including nested NAS/security settings and optional values. The [gNB/AP field reference](docs/GNB_CONFIGURATION.md) explains **every gNB/AP YAML field**, including core addresses, slices and interface rules. The complete files in [`config/container/`](config/container/) are ready to copy and edit.

## Common startup problems

| Message or symptom | What to check |
| --- | --- |
| CMake reports an old source path in `CMakeCache.txt` | Do not ship `build/`. Run `make` from `/UERANSIM`; it moves a copied cache to `build.stale*` and starts a fresh one. |
| CMake cannot find SCTP development files | Install `libsctp-dev` in that container, then run `make`. Cellular gNB runtime also needs SCTP in the host kernel. |
| `Socket bind failed: Cannot assign requested address` or `Wi-Fi startup: staticIP ... is not assigned` | On the **UE container**, run `ip -br -4 addr`. `staticIP` must already be on the exact `Interface` and the interface must be up. On a gNB, verify `linkIp`, `ngapIp` and `gtpIp` are local to that container. |
| `Wi-Fi AP requires distinct valid UeInterface and nextHopInterface names` | Add **both** fields to AP YAML, for example `UeInterface: eth1` and `nextHopInterface: eth2`. They cannot name the same interface. |
| AP firewall setup fails | Check `command -v iptables`, `iptables -w -S UERANSIM_3` for the example AP ID, and whether the container has `CAP_NET_ADMIN`. The actual chain suffix is the gNB ID derived from `nci` and `idLength`; for `nci: '0x1'`, `idLength: 32`, it is `0`. Do not remove a chain owned by another running AP. |
| Cellular UE cannot create a TUN | Expose `/dev/net/tun` and grant network administration capability to the UE container. |
| UE does not discover a gNB/AP | `gnbSearchList` must contain the peer's **`linkIp`**; check IP connectivity and UDP port `4997`. |
| Wi-Fi station selects an AP but cannot reach the uplink | Check AP IPv4 forwarding, `nextHopInterface`, its OS uplink route, and an upstream return route/NAT for the UE subnet. |
| Cellular registration or PDU session fails | Check the core's PLMN, IMSI/key/OPc, DNN and slice, AMF connectivity, and N3/UPF reachability. |
